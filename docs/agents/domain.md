# Domain Docs

How engineering skills consume this repo's domain documentation. Single-context.

## Before exploring, read

- `GLOSSARY.md` at the repo root
- `docs/adr/` entries touching the area you're about to work in

If either is missing, proceed silently. `/domain-modeling` creates them lazily.

## Rules

- Use glossary terms in tickets, proposals and test names. Don't drift to synonyms it avoids. A missing term means reconsider, or note it for `/domain-modeling`.
- If your output contradicts an ADR, say so explicitly: _Contradicts ADR-0007, but worth reopening because…_
